# Should-cost dashboards

`npm run build` writes a small site into `site/`. Open `site/index.html` and pick a model:

| Page | Model |
|---|---|
| `index.html` | Landing page with a card per model |
| `cables.html` | LT and HT power cables |
| `cable-trays.html` | Cable trays and BoQ |
| `busduct.html` | Busduct and FY26 benchmark |
| `structural-steel.html` | Structural steel & PEB |
| `commodity-prices.html` | Viewer/editor for the shared price file |
| `commodity-prices.js` | The shared monthly commodity prices (hand-edited, not generated) |

Each page is self-contained (three.js bundled, no CDN) but they must stay in one folder, because every page loads `commodity-prices.js` from next to it. `should-cost-dashboards.zip` holds the whole folder.

### Commodity prices

Every dashboard has a **Prices** selector in the top bar. *Manual · workbook prices* (default) uses the workbook's own rates and reproduces it exactly. Picking a month fills the commodity-driven rates (copper, aluminium, zinc, XLPE, PVC, steel wire, GI/Al/MS sheet, structural steel) from that month. Editing any of those rates by hand switches back to Manual and keeps the value.

To update prices, edit `site/commodity-prices.js` directly, or open `commodity-prices.html`, edit the table and press *Download commodity-prices.js*, then replace the file in the folder. *Save in this browser* only affects that browser. The months currently in the file are **illustrative sample data** (`"sample": true`), a seeded random walk generated by `scripts/seed-prices.mjs`. Replace with real prices and set `sample` to `false`.

The lines below describe the cable dashboard (`cables.html`).

Its maths is a line-for-line port of the `LT Batch Calculator` sheet in `data/Power_Cable_Batch_Cost_Model_LT_HT_v3.xlsx`.

| Command | What it does |
|---|---|
| `npm i && npm run build` | Rebuilds the pages in `site/` from `src/` (three.js is bundled in) |
| `npm test` | Checks every calculator against its workbook, plus the price file |
| `python3 test/extract.py <xlsx>` | Regenerates `src/data.js` and `test/fixtures.json` after the workbook's tables change |

Edits to prices, cost structure and IS tables are stored in the browser (`localStorage`), and the reset button restores the workbook values.

The cable-tray model is ported from `data/Cable_Trays_Nabinagar_BoQ_Cost_model_300926.xlsx`. Regenerate its test fixtures with `python3 test/extract_tray.py <xlsx>`.

The busduct model is ported from `data/Busduct_Batch_Cost_Model_v7.xls`. It is an .xls, so convert it first (`soffice --headless --convert-to xlsx --outdir <dir> data/Busduct_Batch_Cost_Model_v7.xls`) and run `python3 test/extract_busduct.py <dir>/Busduct_Batch_Cost_Model_v7.xlsx` to regenerate `src/dataBusduct.js` and its test fixtures.

## Structural steel & PEB dashboard

`structural-steel.html` is a separate page: parametric structures (factory shed, pipe rack, façade framing, large-diameter pipe, custom takeoff) feed a steel takeoff, which feeds `data/Structural_Steel_Cost_Model_vTKM.xlsx`.

The workbook is not re-implemented. `src/structural/engine.js` evaluates the workbook's own formulas (`src/structural/workbook.json`, regenerated with `python3 test/extract_structural.py <xlsx>`), so edits to the model flow through. `npm test` checks that the engine reproduces all 966 formula results, that the input mapping reproduces the workbook base case, and a set of property checks. Member sizing for each structure is in `src/structural/takeoff.js`.

Erection is built bottom-up in `src/structural/erection.js` (crane hire and operation, rigging crew, fit-up, bolting, field welding with the workbook's weld-metal rate, MEWPs, site overheads) and replaces the workbook's flat ₹26,000/t. The rate card is editable on the Erection tab.
